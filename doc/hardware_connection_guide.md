## 1. 概述

本指南说明如何将 ESP32-C5 RID 广播模块连接到 ArduPilot 飞控（如 Pixhawk、CubePilot、SpeedyBee 等），通过 UART 接收 MAVLink 飞行数据。

**核心原理：**
- 飞控通过 TELEM1/TELEM2 端口持续输出 MAVLink v2 数据流
- ESP32-C5 通过 UART1 接收这些数据
- 固件中的 MAVLink 解析器提取位置、速度、状态等信息
- 解析结果用于填充 GB 46750-2025 广播数据包

**数据流向：**
```
飞控 TELEM1 TX ──────→ ESP32-C5 GPIO4 (UART1 RX)
        GND ──────────→ ESP32-C5 GND
        
飞控 (MAVLink v2 @ 115200 baud) → ESP32 (解析) → BLE 广播
```

## 3. 飞控 TELEM1 接口说明

### 什么是 TELEM1？

TELEM1 (Telemetry Port 1) 是飞控上的串口通信端口，通常用于：
- 连接数传电台 (如 SiK Radio)
- 连接地面站 (通过蓝牙/WiFi 数传)
- 连接远程识别模块

### TELEM1 引脚定义 (标准 Pixhawk 6P 接口)

```
    ┌─────────────────────┐
    │  1  2  3  4  5  6   │  ← DF13 连接器 (6针)
    └─────────────────────┘
       │  │  │  │  │  │
       │  │  │  │  │  └── 6: 空 (或部分型号为 SENSE)
       │  │  │  │  └───── 5: TX  → 飞控发送 (连接到外部设备 RX)
       │  │  │  └──────── 4: RX  → 飞控接收 (连接到外部设备 TX)
       │  │  └─────────── 3: CTS → 流控 (通常不用)
       │  └────────────── 2: RTS → 流控 (通常不用)
       └───────────────── 1: +5V → 电源输出 (不要连接!)
       (或 GND，取决于型号)
```

**重要提示：**
- 不同飞控的 TELEM1 引脚定义可能不同！
- **务必查阅你的飞控手册确认引脚定义**
- 我们只需要 **TX** 和 **GND** 两根线

### 常见飞控 TELEM1 引脚

| 飞控型号 | 接口类型 | TX 引脚 | GND 引脚 | 备注 |
|---------|---------|---------|----------|------|
| Pixhawk 4 | DF13-6P | Pin 5 | Pin 1 | Pin 1 = GND |
| CubePilot Orange | DF13-6P | Pin 5 | Pin 1 | Pin 1 = +5V |
| SpeedyBee F405 V3 | DF13-6P | Pin 5 | Pin 1 | 参考手册 |
| Matek H743 | DF13-6P | Pin 5 | Pin 1 | Pin 1 = GND |
| Holybro Kakute H7 | DF13-6P | Pin 5 | Pin 1 | 参考手册 |

### 如何找到 TX 引脚？

1. **查阅飞控手册** - 最可靠
2. **看 PCB 丝印** - 很多飞控在 TX 旁边标注 "T" 或 "TX"
3. **用万用表测量** - 上电后，TX 引脚对 GND 有 3.3V 高电平（空闲状态）
4. **连接数传模块测试** - 数传模块能收到数据的那个就是 TX

## 4. ESP32-C5 UART 接口说明

### ESP32-C5 的 UART 资源

ESP32-C5 有 2 个 UART 控制器：

| UART | 默认用途 | 默认引脚 | 可用性 |
|------|---------|----------|--------|
| UART0 | USB 串口调试 (通过 USB-C) | GPIO16 (RX), GPIO17 (TX) | 调试时被占用 |
| UART1 | 通用 GPIO | 可配置 | **推荐用于飞控数据** |

### 为什么选择 UART1？

- UART0 通常用于 USB 调试，与电脑通信
- UART1 完全独立，可以自由分配 GPIO
- 本方案使用 UART1 接收飞控数据，UART0 保留调试

### GPIO 选择

代码中默认配置：
- **UART1_RX: GPIO4** ← 连接飞控 TELEM1 TX
- UART1_TX: 不使用 (单向接收)

**为什么选择 GPIO4？**

| GPIO | 特性 | 适用性 |
|------|------|--------|
| GPIO4 | 通用 IO，无启动约束 | ✅ 推荐 |
| GPIO5 | 通用 IO | ✅ 可选 |
| GPIO6 | JTAG MTMS，用于联锁引脚 | ❌ 已占用 |
| GPIO8-17 | USB/Strapping pins | ❌ 有特殊功能 |

**如果你需要更换 RX 引脚：**
修改 `main/config.h` 中的 `FC_UART_RX_GPIO` 定义。

### ESP32-C5-DevKitC-1 GPIO 布局

```
                    ESP32-C5-DevKitC-1
                  ┌───────────────────────┐
        USB-C ────┤                       ├──── 3V3
                  │    ┌─────────────┐    │
       GPIO0 ─────┤    │             │    ├──── GPIO4 ← 接飞控 TX
       GPIO1 ─────┤    │  ESP32-C5   │    ├──── GPIO5
       GPIO2 ─────┤    │  (WROOM-1)  │    ├──── GPIO6 (联锁)
       GPIO3 ─────┤    │             │    ├──── GPIO7
                  │    └─────────────┘    │
        GND ──────┤                       ├──── GPIO27 (LED)
                  │                       │
                  └───────────────────────┘
```

## 5. 接线方案

### 最小接线 (推荐)

只需要 2 根线：**信号 (TX→RX)** + **共地 (GND→GND)**

```
    飞控 TELEM1                   ESP32-C5-DevKitC
    ┌─────────┐                  ┌─────────────┐
    │         │                  │             │
    │  TX (5) │──────────────────│ GPIO4       │
    │         │                  │             │
    │ GND (1) │──────────────────│ GND         │
    │         │                  │             │
    └─────────┘                  └─────────────┘

    只需这 2 根线！
```

### 接线步骤

**步骤 1: 准备**
1. 确保飞控和 ESP32 都**断电**
2. 准备好 2 根杜邦线（母对母或公对母，取决于接口类型）

**步骤 2: 连接 GND**
1. 找到飞控 TELEM1 的 GND 引脚（参考第 3 节表格）
2. 用杜邦线连接：飞控 GND → ESP32-C5 GND
3. 确保连接牢固，不要碰到其他引脚

**步骤 3: 连接 TX**
1. 找到飞控 TELEM1 的 TX 引脚
2. 用杜邦线连接：飞控 TX → ESP32-C5 GPIO4
3. **再次确认**是 TX (飞控发送) → RX (ESP32 接收)，不是反的

**步骤 4: 检查**
- [ ] GND 连接正确
- [ ] TX→RX 方向正确
- [ ] 没有连接 +5V 或电源引脚
- [ ] 没有短路风险

### 供电方案

ESP32-C5 的供电方式（任选其一）：

| 方案 | 说明 | 推荐场景 |
|------|------|----------|
| USB 供电 | 通过 ESP32 自带 USB-C 口供电 | 桌面调试 |
| 飞控供电 | TELEM1 Pin 1 (+5V) → ESP32 5V 引脚 | 一体化安装 |
| 独立电源 | 电池 + 稳压模块给 ESP32 供电 | 实际飞行 |

**注意：如果同时使用 USB 和飞控供电，注意避免电源冲突！**

## 6. 波特率配置

### 飞控端波特率

ArduPilot 飞控的 TELEM1 默认波特率通常是 **57600**，但可以配置。

**通过 Mission Planner 查看/修改波特率：**

1. 连接飞控到电脑 (USB)
2. 打开 Mission Planner → Config/Tuning → Full Parameter List
3. 搜索 `SERIAL1_BAUD`
4. 常见选项：

| 值 | 波特率 |
|---|--------|
| 57 | 57600 (默认) |
| 115 | 115200 |
| 230 | 230400 |
| 921 | 921600 |

5. 修改后点击 "Write Params" 保存

**通过 QGC 查看/修改波特率：**

1. 连接飞控 → 点击 QGC 图标 → Vehicle Setup → Parameters
2. 搜索 `SERIAL1_BAUD`
3. 修改并保存

### ESP32 端波特率

在 `main/config.h` 中配置：

```c
#define FC_UART_PORT_NUM    1        // UART1
#define FC_UART_RX_GPIO     GPIO_NUM_4
#define FC_UART_BAUD_RATE   115200   // 必须与飞控一致！
```

**重要：两端波特率必须完全一致！**

根据你的 log 数据（你用 sscom 监听时波特率是 115200），飞控端应该已经设置为 115200。

### 验证波特率是否匹配

如果波特率不匹配，你会看到：
- 串口输出全是乱码
- MAVLink CRC 错误
- 解析不到有效数据

## 7. 验证步骤

### 步骤 1: 烧录固件

```bash
cd Drone_Remote_Recognition_Module
idf.py build
idf.py -p COMx flash monitor    # COMx 替换为实际端口
```

### 步骤 2: 检查启动日志

正常启动后应该看到：

```
I (xxx) FLIGHT_DATA: UART1 initialized: baud=115200 rx_gpio=4
I (xxx) FLIGHT_DATA: UART1 RX task started (baud=115200, rx_gpio=4)
```

### 步骤 3: 检查数据接收

连接飞控后，串口每 5 秒会输出状态摘要：

```
I (xxx) FLIGHT_DATA: frames=1234 crc_err=0 armed=0 status=3 fix=3 sats=12 lat=30.148875 lon=120.511457 alt=9.5
```

| 字段 | 含义 | 正常值 |
|------|------|--------|
| frames | 已解析帧数 | 持续增长 |
| crc_err | CRC 错误数 | 应为 0 或极少 |
| armed | 是否解锁 | 0=未解锁, 1=已解锁 |
| status | 系统状态 | 3=STANDBY, 4=ACTIVE |
| fix | GPS 定位类型 | 2=2D, 3=3D |
| sats | 可见卫星数 | ≥8 为佳 |
| lat/lon/alt | 位置/高度 | 应与 QGC 一致 |

### 步骤 4: 验证 BLE 广播

使用 nRF Connect (手机 App) 扫描 BLE 设备：
- 设备名：`ESP32C5_RID`
- Service UUID：`0x0D50`
- 应能看到 77 字节的 Service Data

### 步骤 5: 对比数据

将 ESP32 解析的数据与 QGC 显示对比：
- 纬度/经度应一致（误差 < 0.00001°）
- 高度应一致（误差 < 1m）
- 航向应一致（误差 < 5°）

## 8. 故障排除

### 问题 1: 无数据输出

**现象：** 串口一直不显示 `frames=xxx`

**排查步骤：**
1. 检查接线是否正确（TX→RX, GND→GND）
2. 确认飞控已上电
3. 确认飞控 TELEM1 端口输出 MAVLink 数据（用 QGC/Mission Planner 测试）
4. 用万用表测量飞控 TX 引脚电压（应为 3.3V 左右）

### 问题 2: CRC 错误很多

**现象：** `crc_err` 数值持续增长

**原因：**
1. 波特率不匹配
2. 接线接触不良
3. 电磁干扰

**解决：**
1. 确认 `FC_UART_BAUD_RATE` 与飞控 `SERIAL1_BAUD` 一致
2. 重新插拔杜邦线，确保接触良好
3. 使用屏蔽线或缩短线缆长度
4. 飞控和 ESP32 共地

### 问题 3: 数据超时 (STALE)

**现象：** 日志显示 `Data STALE`

**原因：** 超过 2 秒未收到有效位置数据

**排查：**
1. 检查 GPS 是否锁定（fix >= 2）
2. 检查卫星数（sats >= 4）
3. 如果在室内，GPS 信号弱是正常的
4. 检查 `frames` 是否在增长

### 问题 4: 位置数据为 0

**现象：** lat=0, lon=0

**原因：** GPS 未锁定

**解决：**
1. 将无人机/飞控移到室外或靠窗位置
2. 等待 GPS 锁定（通常需要 1-3 分钟）
3. 确认 GPS 模块正常连接

## 9. 常见问题

### Q1: ESP32-C5 的 USB-C 口可以直接接飞控吗？

**不能。** USB-C 口连接的是 UART0，通过 USB 转 UART 芯片（如 CH340/CP2102）。这个口用于连接电脑调试，不能直接接飞控的 TTL 电平输出。

飞控数据必须通过 **GPIO 引脚**（UART1）接入。

### Q2: ESP32-C5 标记 "UART" 的 Type-C 口是什么？

有些 ESP32-C5 开发板有一个标记 "UART" 的 Type-C 口。这通常是：
- **情况 A**：UART1 的 TX/RX 通过 USB-C 接口引出，用于连接外部串口设备
- **情况 B**：第二个 USB 转 UART 芯片（如 CH340），将 UART1 转为 USB

如果是情况 A，**不能直接连接飞控**，因为 Type-C 接口可能有电平转换电路。

**建议：** 直接用杜邦线连接 GPIO4，这是最可靠的方式。

### Q3: 可以同时连接电脑调试和飞控吗？

**可以。** 接线方案：

```
电脑 USB ──→ ESP32 USB-C (UART0 调试)
飞控 TX ──→ ESP32 GPIO4 (UART1 数据)
```

两个 UART 独立工作，互不干扰。

### Q4: 需要连接 RX→TX 吗？

**不需要。** 本方案是**单向接收**：
- 飞控 → ESP32：需要（飞控 TX → ESP32 RX）
- ESP32 → 飞控：不需要

如果你需要 ESP32 向飞控发送命令（如配置参数），才需要接 RX→TX。

### Q5: 不同飞控的 TELEM 端口速度一样吗？

不一样。常见配置：

| 飞控 | TELEM1 默认 | TELEM2 默认 |
|------|------------|------------|
| Pixhawk 4 | 57600 | 57600 |
| CubePilot | 57600 | 57600 |
| SpeedyBee F405 | 115200 | 57600 |
| Matek H743 | 57600 | 115200 |

**务必查阅你的飞控手册！**

### Q6: 为什么我收到乱码？

可能原因：
1. **波特率不匹配** — 最常见，检查两端设置
2. **数据位/停止位/校验位不一致** — 飞控和 ESP32 都要设为 8N1
3. **接线错误** — TX/RX 接反了
4. **电平不匹配** — 确认飞控是 3.3V TTL（不是 RS-232）
